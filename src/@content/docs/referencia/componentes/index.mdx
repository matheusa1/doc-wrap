## O que já existe hoje

Os componentes de MDX do projeto vivem em `src/@presentation/components/docs`. Eles foram feitos para complementar a escrita em Markdown, não para substituí-la. Em geral, vale começar por texto corrido e só introduzir um componente quando houver ganho real de legibilidade.

Além dos componentes importados, o template também já oferece dois recursos automáticos. Blocos `mermaid` são convertidos em diagramas sem import manual, e expressões LaTeX são renderizadas com KaTeX dentro do pipeline de MDX.

## Imports e recursos automáticos

Componentes como `Callout`, `Cards`, `Steps`, `FileTree`, `Tabs`, `TabItem` e `DataTable` exigem import explícito com o alias `@presentation`. Já Mermaid e KaTeX entram pelo pipeline configurado em `vite.config.ts`, então não dependem de um componente importado no topo do arquivo.

Essa distinção é importante para manter os exemplos corretos e evitar imports desnecessários em MDX.
