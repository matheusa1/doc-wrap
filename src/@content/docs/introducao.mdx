## O que este projeto entrega

Este template foi montado para publicar duas trilhas de conteúdo a partir de arquivos MDX. A primeira é a central `/docs`, pensada para guias permanentes, documentação funcional e material de implantação. A segunda é a área `/blog`, voltada a notas de versão, comunicados operacionais e publicações com contexto de data.

O conteúdo fica em `src/@content`, enquanto a aplicação React, o layout, os componentes de MDX e os mapas de navegação vivem em `src/@presentation`. Essa separação ajuda a evoluir o template sem misturar regras visuais, carregamento de conteúdo e escrita editorial.

<Callout title="Fonte de verdade" type="info">
  O projeto atual usa `src/@content/docs/**/*.mdx` para documentos e `src/@content/blog/**/*.mdx` para publicações. Referências antigas a `src/docs` ou `src/blog` não representam mais a estrutura real do template.
</Callout>

## Como a base funciona

O carregamento das páginas é automático com `import.meta.glob`, então a rota pública nasce do caminho do arquivo. A documentação também já entrega sidebar, breadcrumb, índice lateral com `h2` e `h3`, tema claro e escuro, busca local no desenvolvimento e índice Pagefind no build de produção.

O suporte a MDX inclui componentes visuais prontos, blocos `mermaid` renderizados automaticamente e fórmulas com KaTeX. Isso permite manter a escrita em Markdown na maior parte dos casos e recorrer a componentes apenas quando eles realmente deixam a explicação mais clara.

## Quando personalizar o quê

Se a mudança for editorial, trabalhe primeiro em `src/@content`. Se a mudança for de layout, navegação, tema ou comportamento da interface, o ponto de entrada costuma estar em `src/@presentation`. Se a necessidade for enriquecer a escrita com novos blocos, o lugar certo é `src/@presentation/components/docs`.

<Callout title="Primeiro passo recomendado" type="hint">
  Antes de mudar estrutura ou componentes, substitua os conteúdos de exemplo pela documentação real do sistema. Isso costuma revelar com mais clareza quais ajustes o template realmente precisa.
</Callout>
